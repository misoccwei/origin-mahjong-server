# origin-mahjong-server

《原點麻將》（HKRN Studio，CC BY-SA 4.0）的多人連線伺服器與網頁客戶端。

規則書：<https://github.com/originmahjong/origin-mahjong-rules>單一 Node.js process，不使用資料庫，所有狀態都存在記憶體中。

## 快速開始

```bash
npm install
npm run build        # 型別檢查 + 建置前端到 dist/client
npm start            # http://localhost:3000
```

開發模式（前後端熱更新）：

```bash
npm run dev          # 後端 :3000
npm run dev:client   # 前端 :5173，/ws 會 proxy 到 :3000
npm test             # 全部測試（單元 + 引擎模擬 + WebSocket 整合）
npm run test:fast    # 略過較慢的 AI 整場模擬
```

> `npm start` 不會自動重新載入：更新程式或重新 `npm run build` 之後，一定要重新啟動伺服器。網頁與伺服器的協定版本（`PROTOCOL_VERSION`）不一致時，網頁會顯示「伺服器版本與網頁版本不一致」並停止連線，而不是讓畫面壞掉。開發時用 `npm run dev` 會自動重新啟動。

環境變數：`PORT`（預設 3000）、`HOST`、`STATIC_DIR`、`AI_DELAY_MS`（AI 每步延遲，預設 700）、`ICE_SERVERS`（語音用的 STUN／TURN，JSON 陣列，預設為 Google 公用 STUN）。

> 瀏覽器的 WebCrypto 只在**安全來源**（HTTPS 或 localhost）可用。部署到區網／公網時請放在 HTTPS 反向代理後面，否則無法建立身分金鑰。


### 伺服器握有全部牌局狀態

牌山與手牌只存在伺服器端。每位玩家只收到自己能看的快照（自己的手牌、所有人的捨牌與鳴牌、他人手牌張數）。對手的暗槓一律遮蔽（局結束後也是），只有局結果中公開手牌的座位（和牌、聽牌、主動展示）才連同暗槓一起顯示。

### 身分識別（不需資料庫）

1. 瀏覽器第一次開啟時產生金鑰對（Ed25519，不支援時改用 ECDSA P-256），存在 localStorage。
2. 連線後伺服器送出隨機 `nonce`，客戶端用私鑰對 `origin-mahjong-auth:<nonce>` 簽章。
3. 伺服器驗證簽章後，以公鑰指紋（SHA-256 前 22 字元）作為**使用者代碼**。

同一個瀏覽器重連會得到相同代碼，因此可以回到原本的座位；其他人無法冒用。之後要改成帳號登入時，只需替換 `auth` 這一步產生 userId 的方式。

### 暱稱

暱稱在所有保留中的使用者之間不可重複（不分大小寫、NFKC 正規化）。使用者斷線後暱稱會保留 10 分鐘；人還在房間裡的話會一直保留。

### 房間與牌局流程

- 大廳的房間列表會列出等待中、還有空位的房間（可「加入」），以及允許觀戰的房間（可「觀戰」，含對局中與已坐滿的房間），每 3 秒更新；也可以輸入 4 位數房號加入或觀戰。
- 建立房間時取得 4 位數房號。房主可以設定規則、加入或移除 AI、移除玩家。
- 座位坐滿、其他真人都按「準備」後，由房主按「開始」。開啟「隨機座位」（預設開啟）時，開始時會打亂座位順序（讓分設定跟著玩家走）。
- 圈數：一圈等於「人數」局。預設 2 人 2 圈、3 人 2 圈、4 人 1 圈。
- 每局結束顯示結果，所有真人按「下一局」後繼續，或倒數結束後自動繼續（房主可設定「結算倒數」，預設 20 秒，0 = 等所有人按）。結果畫面每位玩家一張卡片：和牌者顯示和牌與牌型；聽牌者顯示所聽的牌，以及**得分最高的和法**（和哪張、自摸或銃和、牌型），聽牌得分就是依它計算；其他人的手牌不會送到別人的瀏覽器，但可以自己按「展示我的手牌」公開。
- 全部打完後顯示結算畫面，房主可以「加一圈」（分數接續），或「回到房間重新開始」。
- 結算畫面的各局紀錄可以點任一局**重看那一局的結果**（和牌、聽牌、牌型、分數；手牌一樣只公開和牌、聽牌、主動展示的，以及自己的），可切換上一局／下一局並匯出圖片。加一圈後再結算時，之前的局也都看得到；回到房間重新開始才會清空。
- 每局結果與最終結算畫面都有「匯出圖片」按鈕：把結果畫成 PNG，手機用系統分享（可以存到相簿），電腦直接下載。

### 觀戰

- 房主可在規則設定中開關「允許觀戰」（預設允許）；關閉時現有觀戰者會被請出。
- 觀戰者不佔座位，**只看得到公開資訊**（河、鳴牌、分數、各家手牌張數），跟玩家看對手一樣；暗槓一律遮蔽，局結果只看得到和牌、聽牌與主動展示的手牌。伺服器不會把任何人的手牌送給觀戰者。
- 觀戰時可以切換坐在下方的視角，不能操作、不能按「下一局」，也**不能參與語音**（伺服器不轉送觀戰者的語音 signaling）。
- 等待中有空位時，觀戰者可以按「入座」成為玩家。
- 觀戰者斷線超過 60 秒會被移出；房間關閉時一起回到大廳。

### 語音

以房間為單位的語音頻道（WebRTC P2P mesh，最多 4 人，伺服器只轉送 signaling，不經手音訊）：

- **房主開始牌局時自動開啟**，直到離開房間（或房間關閉）才關閉；牌局結束回到等待／結算畫面時仍保持。AI 沒有語音。
- 預設喇叭開、**麥克風關**（只收聽）；按下麥克風按鈕時瀏覽器才會要求麥克風授權，拒絕或找不到麥克風時維持只收聽，之後可以再按麥克風按鈕重試。
- 牌桌工具列有麥克風、喇叭開關；⚙ →「語音設定」可以選擇麥克風裝置、開啟**按鍵說話**（按住 V 鍵或畫面上的「按住說話」），並對每位玩家單獨靜音。等待房間與結算畫面也有語音區塊。
- 名字旁會顯示說話中、對方麥克風關閉、被你靜音的圖示；麥克風裝置與按鍵說話設定、個別靜音記在瀏覽器（localStorage）。
- 需要安全來源（HTTPS 或 localhost）才能使用麥克風。嚴格 NAT／行動網路下 P2P 可能連不上，請以 `ICE_SERVERS` 設定 TURN。
- 校驗：`rtc` 訊息只會轉給同房間的真人；`GET /ice-servers` 提供 ICE 設定給網頁。

### 斷線處理

牌局中有真人斷線或離開時，**牌局暫停**：

- 由房主決定「交給 AI 代打」或「解散牌局」，也可以什麼都不選、等玩家回來（回來後自動繼續）。
- 房主本人不在時，由房主的下家（依座位順序第一位在線的真人）決定。
- 暫停期間任何人都可以離開房間。
- 被 AI 代打的玩家重新連線後，會自動拿回控制權。

牌局中如果已經沒有真人在打（都離開了，或都交給 AI 代打），只剩 AI 互打沒有意義，牌局會直接結束（解散）。

在等待中的房間斷線超過 60 秒會被移出座位。所有真人都離線超過 10 分鐘的房間會被關閉。

### 多國語言

- 支援繁體中文、English、日本語。第一次開啟時依瀏覽器語言決定，之後可以在暱稱畫面、大廳、等待房間、牌局中右上角的 ⚙ 選單（觀戰時在工具列）切換，記在瀏覽器（localStorage）。切換立即生效，不需要重新整理，也不會中斷牌局。
- 翻譯以繁體中文原文為 key（`t('房間已滿')`），英日文字典在 `src/client/i18n/`。伺服器送來的錯誤訊息是固定的中文字串，網頁端用同一份字典翻譯，所以協定不需要改；牌型名稱、種類與說明也一樣。電腦的名字（伺服器取的「電腦 N」）依語言顯示。
- `test/client/i18n.test.tsx` 會掃描程式中所有中文字串（網頁、伺服器訊息、牌型），缺少英日文翻譯、翻譯的 `{變數}` 不一致或字典有多餘的字串都會失敗。新增或修改中文字串時要一起補翻譯。
- 版面：英日文字比較長的按鈕（例如手機直式的工具列）可以縮小、必要時以…截斷，不會把畫面撐開；320～1280px 寬、直式與橫式都檢查過三種語言。

### 全螢幕與橫式

- 按下需要伺服器處理的按鈕（登入、建立／加入房間、打牌、吃碰槓等）後，等待回覆期間按鈕會轉圈圈，其他按鈕暫時按不了，避免連點或亂點。
- 牌局畫面固定佔滿整個視窗、不會捲動。直式：最上方是倒數（放大）與局數，接著是分頁資訊卡（提示：輪到誰、聽牌與預計得分或牌效率；推薦牌型；換三張紀錄），高度隨剩餘空間伸縮，矮的手機上最少保留一行；下面是正方形牌桌、手牌與工具列；橫式（寬高比 ≥ 5:4，包含電腦與手機橫放）：手牌在最下面一排、牌桌置中，左側是提示與工具列，右側最上面是局數與倒數，下方是推薦牌型。
- 支援「加到主畫面」（PWA）：以全螢幕 App 的方式開啟，不會出現瀏覽器的網址列與工具列（iOS Safari：分享 → 加入主畫面；Android Chrome：選單 → 安裝應用程式）。支援的瀏覽器在 ⚙ 選單裡也有「全螢幕」按鈕。
- Service Worker 只用來讓網站可以安裝，不快取任何檔案，避免舊版網頁與伺服器版本不一致。

### 牌桌

仿照雀魂的配置：自己在下方，下家在左（旋轉 90°）、對家在上（180°）、上家在右（270°）（原點麻將為順時針），四家的捨牌圍繞在中央面板四周。各家的門風與分數放在牌桌四角的名牌裡，輪到的人會亮起；中央面板只顯示剩餘張數（放大）與剛打出的牌。

### 牌桌上的輔助功能

- 手指著（滑鼠移上或手機點選）手牌中的一張牌時，所有人河裡同種的牌會標紅。
- 輪到自己時指著一張牌，如果打出後會聽牌，提示列會列出聽的每一張牌、剩幾張，以及**和那張牌能和成的牌型與總分**（自摸或銃和取高、不含偶然類）。例如聽四、七筒，但只有四筒有一氣通貫，就會分開顯示，可以當作打哪張的依據；未達和牌最低分數的會標明不能和。
- 聽牌時，手牌上方顯示**預計得分**（所有聽的牌 × 自摸／銃和的最低～最高分，同分只寫一個），下面逐張列出聽的牌、剩餘張數（只扣掉自己看得到的牌）、**和這張的分數與牌型**（自摸與銃和分數不同時分開寫，例如「自摸 60・銃和 55 分」；不含偶然類）；未達和牌最低分數的標明不能和，只有銃和未達時標明只能自摸。
- 「自摸」「和」「搶槓」按鈕上直接寫**現在和的分數**，下面一行是牌型（由伺服器實際計分，含海底、河底、嶺上、搶槓等偶然類；牌型太長時最多兩行，完整的看聽牌列表）。
- 牌型表：首頁有完整的牌型表，可依種類或分數篩選，附條件說明與牌例；牌局中從 ⚙ 選單開啟（預設只列出這桌適用的牌型）。
- 推薦牌型：按工具列的「推薦」開啟面板。最上面是不看牌型的「最快和牌」，下面依期望值列出各牌型，每個牌型一列：牌型名稱、向聽數、分數與**和牌率**，下面用牌直接畫出怎麼湊——劃掉的是該打的牌（輪到自己時），箭頭後面是要的牌（有效牌，扣掉河裡、鳴牌等看得到的牌；太多時只列前幾種）。只能自己摸進來的牌型標「門清」。估計方式的說明收在「說明」裡。和牌率分兩種算法：只限定牌種的牌型（清一色、混一色、斷么九、全帶么九）依向聽數與有效牌估計，越接近聽牌有效牌越少（曲線以模擬自摸打牌擬合）；一定要拿到某幾張特定牌的牌型（番牌、三元、一氣通貫、三色同順、三暗刻、七對子、碰碰和、四暗刻、十三么九、五門齊）則算「那幾張牌在剩下的巡數內拿得到的機率」（剩幾張、刻子能碰、順子能吃上家），再乘上其餘部分的和牌率——這類牌型的有效牌多半是其餘部分的牌，只看有效牌會嚴重高估（例如只有一張中的番牌、還差很遠的五門齊）。同一牌型的不同做法（哪一種番牌、三色同順的數字、一氣通貫的花色）分開估計、只列最好的一種。每巡也有被他家先和的機率。以隨機配牌模擬驗證，各牌型的估計和牌率與模擬結果相差在 1.5 倍以內。期望值 = 和牌率 ×（牌型分數＋底分），依期望值排序，未達和牌最低分數或和牌率不到 1% 的牌型不列出。牌型分成**可吃碰**與**門清（只能自己摸進來）**兩組：門清牌型（七對子、三暗刻、四暗刻、十三么九）只有最後聽牌時能銃和，其他時候只算自己摸牌。各牌型的向聽數同時符合和牌形與牌型條件：番牌、三元、一氣通貫、三色同順、三暗刻以「指定的面子還缺幾張＋其餘部分湊成剩下面子與雀頭的向聽數」計算，五門齊以「每類剛好一組」計算，限定牌種的牌型（清一色、混一色、斷么九、全帶么九等）會算進孤張不夠時要多摸的張數；`test/shared/recommendShape.test.ts` 以隨機手牌與牌型表牌例驗證「評估為聽牌就一定和得出這個牌型」「做得到的牌型不會算遠」「每個向聽數都能一步一步前進」。會參考已經出現過的牌（河裡、鳴牌、自己的槓子）：需要的牌已經沒有剩的牌型不推薦（例如四張一萬都在自己的槓子裡，萬子的一氣通貫就不可能）。
  - 面板上方可以切換**普通型**（上面這種，一次看一個牌型）與**進階型**（結果導向，記在瀏覽器）。進階型往下展開「拿到哪張 → 打哪張」直到和牌：拿牌的方式有自己摸、碰（任何一家打出）、吃（上家打出），聽牌時可以自摸或銃和；每巡各事件的機率依剩下的張數估計，再依剩下的巡數逐巡計算，所以「快但便宜」與「慢但高分」可以直接比較，每一步也都可以選擇不要（摸切、不鳴）。一向聽以內也會考慮只為了做牌而鳴（例如碰中：向聽數不變但多了番牌），已聽牌時另外考慮摸到某張後改聽（例如聽的牌未達和牌最低分數，要摸到中改成番牌才能和）。和牌分數用實際計分（自摸、銃和分開算，不含偶然類），未達和牌最低分數的和法不算。每種打法列出**和牌率與期望得分**（依期望得分排序），下面依第一張拿到的牌（再進／碰／吃／聽／摸到改聽）分組，顯示最可能的和法與分數、經由這組牌和牌的機率；手上多一張時依打哪張分開列；別人剛打出自己可以碰、吃的牌時，會把「碰／吃之後打哪張」與「不鳴」一起比較。只計算 2 向聽以內；計算可能要幾百毫秒，畫面會先顯示再計算。寬螢幕放在牌桌右邊，窄螢幕放在操作列下方，不會蓋到牌桌與按鈕。
- 自動和牌（工具列「自動和」）：和牌分數達到這副聽牌可能的最高分時自動和；沒達到最高分時會停下來讓你自己決定要不要和；**只維持一局**，下一局自動關閉。
- 不鳴牌（工具列「不鳴牌」，和「自動和」「自動打」放在一起）：別人打牌時不吃、不碰、不明槓，自動略過；能和的時候仍會停下來讓你決定（或交給自動和牌）。自己回合的暗槓、加槓不受影響。設定**持續有效**，直到自己關掉。
- 自動摸打（工具列「自動打」）：不換牌、不鳴牌、摸什麼打什麼；和牌達到這副聽牌可能的最高分時自動和，沒達到時和能槓的時候一樣會停下來讓你決定（和不和、槓或「不槓（摸切）」）；**只維持一局**，下一局自動關閉（其他人會看到「自動」標記）。

### 操作

- 點選手牌後，牌桌下緣的固定位置會出現「打出」按鈕（和自摸、暗槓在同一排，不會跟著牌移動；也可以再點一次同一張牌打出）。
- 換三張選牌：點手牌，牌會移到牌桌下緣的 3 個候選格；點候選格放回手牌。候選格滿了再點別張，最早選的那張會回到手牌。
- 鳴牌（吃碰槓和）時限預設 15 秒。
- 吃、碰、槓、和、自摸是疊在牌桌下緣的大按鈕；刻意不放在正中間，因為中間顯示著剛打出的牌，鳴牌時要看得到是哪一張。
- 手牌與鳴牌是兩個獨立區塊（直式時鳴牌在手牌下方另一排）。牌的大小只依鳴牌組數決定、摸牌的位置一直保留，所以摸牌時手牌不會移動或換行。

### 計時

打牌與鳴牌都有時限（房主可設定，0 = 不限）。輪到自己打牌時可以按「長考 +60 秒」延長一分鐘，每局限用一次。逾時的話，打牌會自動打掉摸到的牌，鳴牌會自動略過。

## 測試

測試目錄對應 `src/` 的架構：

```
test/
  shared/            純函式：牌型與分數（scoring）、結算（settlement）、規則設定（rules）、
                     推薦牌型（recommend／outcome，recommendShape 驗證向聽數符合和牌形）、牌型表牌例（yakuInfo）、協定版本（protocol）
  server/
    engine/          一局的狀態機（hand，用指定牌山重現情境）、局數輪替（match）、
                     AI 與自動摸打（ai）、AI 打完整場的模擬（simulation，較慢）
    room.test.ts     房間的單元測試（假時鐘、固定亂數：隨機座位、結算倒數）
    server.test.ts   WebSocket 整合測試（登入、房間、觀戰、語音 signaling、斷線、整場流程）
  client/            畫面（伺服器渲染快照）：牌桌、局結果、大廳／等待房間／最終結算、牌型表、多國語言
  support/           共用工具：牌的寫法（tiles）、指定牌山與 AI 對局（hand）、WebSocket 測試客戶端（wsClient）、
                     畫面快照（snapshots）、翻譯字串清單（i18nKeys）
```

- 畫面測試比對「看得到的文字」（`support/snapshots.tsx` 的 `text()`），不比對 React 插入的標記，改版面不會誤報。
- 協定版本測試只看 `protocol.ts` 的程式（註解除外）；改了訊息或快照格式要把 `PROTOCOL_VERSION` 加一。

## 已支援的規則

- 基本規則（6 大類牌型）
- 進階規則（預設開啟）：和牌×2＋聽牌得分、5 大類進階牌型
- 和牌最低分數：和牌分數（底分＋牌型分數）未達此分數不能和牌，預設 20（0 = 不限）
- 換三張（房主可開關，預設開啟）：配牌後每人可選擇換或不換，換的話必須剛好 3 張、交給下家；全部人決定後才同時交換，其他人看不出誰有沒有換。交換後在牌桌正中間亮出換出與收到的牌（收到的牌依序翻開），3 秒後才放進手牌（沒人換也會等 3 秒，避免從等待時間看出來）。之後換出與收到的牌整局顯示在牌桌下緣
- 零和式計分（包含放銃包付、同巡跟打免責）
- 讓分（每人的基本底分，未設定時基本規則 20、進階規則 0）
- 電腦難度：初學者（大多亂打）、簡單（只看向聽數、偶爾亂打、不鳴牌）、普通、困難（對手看起來聽牌時會避開危險牌）。普通與困難會以推薦牌型中期望值最高的牌型為目標：和牌最低分數高於自己的底分時，打牌以朝目標牌型為優先，鳴牌也只在鳴了之後期望值變高時才鳴；換三張依目標牌型換出最沒用的 3 張。初學者與簡單有一半機率隨便換三張。房主可以在等待房間或牌局中隨時調整，立即生效，不會重設準備狀態
- 2／3／4 人，王牌分別為 56／34／12 張

- 牌型擴充包（房主可開關，預設開啟）：依規則書補頁草稿加入 20 個牌型——小二元／大二元、小二風／大二風、連面子／二龍戲、三連環／四連環、三連跳／四連跳、鏡面子／鏡同和、三色連環、三色連跳、四歸一／八歸一／十二歸一、十三不搭、線對稱、點對稱。

尚未支援：花牌、鳴牌得分玩法（暗吃、暗碰、暗對）。
